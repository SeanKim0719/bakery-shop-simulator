# 0003. 싱글톤 대신 부트스트랩(Composition Root)으로 연결

- 상태: 확정
- 날짜: 2026-10-15

## 상황

시스템이 10개 이상이고 서로를 참조한다 (오븐은 창고와 도감을, 손님은 선반·가격·계산대를). 이 참조를 어떻게 연결할지 정해야 했다.

## 선택지

1. **싱글톤** (`GameManager.Instance`): 가장 빠르게 만들 수 있다. 대신 초기화 순서가 `Awake` 실행 순서에 묶이고, 어디서나 접근할 수 있어 의존 관계가 코드에 드러나지 않으며, 단위 테스트에서 교체하기 어렵다. 도메인 리로드를 끄면 static 값이 플레이 모드 사이에 남는다.
2. **DI 프레임워크** (VContainer, Zenject): 구조는 깔끔하지만 프레임워크 학습과 설정이 8주 일정에 부담이고, 면접에서 "프레임워크가 해준 것"과 "내가 설계한 것"의 경계가 흐려진다.
3. **직접 작성한 부트스트랩**: 씬 하나에 `GameBootstrap`을 두고, 시스템을 생성자로 만들어 순서대로 연결한다.

## 결정

3번, 직접 작성한 부트스트랩을 쓴다. 시스템은 생성자 주입, 씬 오브젝트는 `Init(GameContext)` 주입이다.

## 이유

- 초기화 순서가 코드 한 곳에 순서대로 적혀 있어 null 참조 문제를 원천적으로 줄인다.
- 각 시스템이 생성자에서 무엇을 받는지가 곧 의존 관계 문서가 된다.
- 순수 C# 시스템을 테스트에서 가짜 의존성과 함께 바로 생성할 수 있다.
- DI의 원리를 프레임워크 없이 직접 구현했다는 점을 설명할 수 있다.

## 결과와 트레이드오프

- 새 시스템을 추가할 때마다 부트스트랩을 직접 고쳐야 한다. 시스템 수가 20개 수준이라 감당 가능하다.
- 런타임 생성 오브젝트는 팩토리를 거쳐야 주입되므로, `Instantiate`를 아무 데서나 직접 호출하지 않는 규칙이 필요하다.
