# 0006. 신선도를 실시간 대신 날짜 단위로

- 상태: 확정
- 날짜: 2026-10-15
- 기획서 변경: GDD 4.4 "신선도는 시간에 따라 떨어진다" → 날짜 단위로 수정

## 상황

기획서에는 진열된 빵의 신선도가 시간에 따라 떨어진다고 적었다. 설계 단계에서 이것을 실시간으로 처리할지 정해야 했다.

## 선택지

1. **실시간 신선도**: 빵마다 구운 시각을 저장하고 매 순간 신선도를 계산한다. 현실감은 있지만, 준비 단계에는 영업 시계가 멈춰 있어 어떤 시계 기준으로 떨어뜨릴지 애매하다. 선반의 빵마다 표시를 갱신해야 하고, 플레이어가 6분짜리 하루 안에서 신선도 차이를 체감하기도 어렵다.
2. **날짜 단위 신선도**: 빵마다 `daysOld`만 두고, 하루 마무리 때 1씩 올린다. 보관 일수를 넘기면 폐기한다.

## 결정

2번, 날짜 단위로 관리한다.

## 이유

- 플레이어의 핵심 판단은 "오늘 몇 개 구울지"이고, 그 결과는 다음 날 남은 빵과 폐기로 드러난다. 날짜 단위가 이 판단과 정확히 맞는다.
- 시계 두 개 중 어느 쪽을 따를지 같은 애매함이 사라진다.
- 빵 하나의 상태가 정수 하나라 세이브와 테스트가 쉽다.

## 결과와 트레이드오프

- 영업 중에 빵이 점점 상해 가는 긴장감은 없다. 대신 하루 지난 빵은 구매 확률이 떨어지고, 보관 일수를 넘기면 폐기 손실로 정산에 드러난다.
