# M1. 조작과 상호작용

> 끝났을 때 되는 것: 그레이박스 매장을 걸어 다니며 박스를 들고, 쌓고, 내려놓는다. 재미 포인트 F1의 바탕이다.

코드는 [PR #1](https://github.com/SeanKim0719/bakery-shop-simulator/pull/1)에 있다. 남은 일은 Unity에서 확인하고, 그 과정에서 나온 버그 두 건을 트러블슈팅 기록으로 남기는 것이다. 설계는 [04. 플레이어와 상호작용](../design/04-player-interaction.md)에 있다.

## M1-01. PR #1 확인과 병합

**목적**: PR #1의 조작이 Unity에서 의도대로 동작하는지 확인하고 `main`에 병합한다.

**Unity에서 확인**

- [ ] Test Runner → EditMode → Run All: 46개가 모두 통과한다.
- [ ] 메뉴 **BakeryShop → 그레이박스 씬 만들기 (1주차)**로 씬을 만들고 플레이한다. 콘솔에 오류가 없다.
- [ ] WASD로 걷고 마우스로 둘러본다. 벽과 가구를 통과하지 않는다. 위아래 시점이 ±80도에서 멈춘다. 25cm 턱을 올라간다.
- [ ] 박스를 바라보면 `[E] 배송 박스 들기`가 뜨고(한글이 □로 나오지 않는다), E를 누르면 손에 든다.
- [ ] 박스를 든 채 바닥을 보면 `[E] 내려놓기`가 뜨고, 놓인 박스가 바닥에 반듯하게 선다.
- [ ] 박스를 든 채 다른 박스의 윗면을 보고 E를 누르면 그 위에 쌓인다. 3단까지 쌓아도 무너지지 않는다.
- [ ] G를 누르면 앞에 떨어뜨린다.
- [ ] **버그 1 확인**: 박스를 든 채 벽과 파란 가구에 바짝 붙어도 박스가 파고들지 않고 몸 쪽으로 당겨진다. 물러서면 원래 거리로 돌아온다.
- [ ] **버그 2 확인**: 박스를 발밑에, 몸과 겹치게 내려놓으려 하면 안내가 뜨지 않거나 놓이지 않는다. 플레이어가 박스 위로 올라가지 않는다.
- [ ] Esc를 누르면 커서가 풀리고, 다시 누르면 잠긴다.

**확인하면서 적어 둘 것**: 들고 걷는 느낌에서 어색한 점 (박스가 시야를 너무 가리는지, 당겨질 때 튀는지, 내려놓는 위치가 예상과 다른지). 수치는 `Hands`와 `PlayerMotor`의 인스펙터에서 바꿔 보고, 좋았던 값을 PR에 댓글로 남긴다.

**의존**: 없음

## M1-02. 트러블슈팅 기록 2건

**목적**: 첫 플레이 테스트에서 나온 버그 두 건을 포트폴리오에 쓸 수 있는 기록으로 남긴다.

수정은 끝났지만 기록은 커밋 메시지에만 있다. GitHub Issues에 **트러블슈팅** 템플릿으로 두 건을 만들고, PR #1의 해당 커밋을 연결한다.

| 이슈 | 현상 | 수정 커밋 | 기록할 핵심 |
| --- | --- | --- | --- |
| 손에 든 물건이 벽에 파고든다 | 박스를 들고 벽이나 가구에 다가가면 박스가 안으로 들어간다 | `8bce1fd` | 원인: 들고 있는 동안 박스의 충돌을 꺼 두어 몸만 벽에 막혔다. 해결: 카메라에서 BoxCast를 하고 막힌 만큼 몸 쪽으로 당긴다 (B안). 버린 대안: 오버레이 카메라, 플레이어 이동 막기 |
| 몸과 겹치게 내려놓으면 플레이어가 위로 올라간다 | 박스를 발밑에 걸치게 놓으면 플레이어가 박스 위에 올라선다 | `ba0edc2` | 가설 1: 공간 검사가 CharacterController의 스킨 두께를 보지 않는다. 가설 2: 검사가 플레이어 몸을 아예 보지 못한다. 검증 방법과 결과, 버린 대안 2가지 |

**버그 2의 가설 검증 방법** (아직 직접 확인하지 않았다)

1. 수정 전 커밋(`8bce1fd`)을 체크아웃한다.
2. 박스를 든 채 **바로 발밑**을 본다. `[E] 내려놓기`가 뜨면 가설 2다 (검사가 몸을 아예 보지 못함).
3. **발 바로 옆, 몸에 반쯤 걸치는 곳**을 본다. 여기서만 뜨면 가설 1이다 (몸의 가장자리, 스킨 두께만큼을 놓침).
4. 3번 위치에서 10번 내려놓아 플레이어가 위로 올라가는 횟수를 센다.
5. 수정 후 커밋(`ba0edc2`)에서 같은 위치를 본다. 안내가 뜨지 않고, Scene 뷰에 빨간 상자와 노란 캡슐이 겹쳐 보이는 것을 캡처한다.

**남길 증거**: 수정 전후 GIF 각 1개, 재현 횟수(예: 10번 중 7번 → 0번), Scene 뷰 캡처.

**Unity에서 확인**

- [ ] 이슈 두 건이 템플릿의 모든 항목(현상, 가설, 검증, 원인, 해결, 결과)을 채우고 있다.
- [ ] 각 이슈에 수정 전후 GIF가 붙어 있다.

**의존**: M1-01
