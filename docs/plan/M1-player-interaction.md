# M1. 조작과 상호작용

> 끝났을 때 되는 것: 그레이박스 매장을 걸어 다니며 박스를 들고, 쌓고, 내려놓는다. 재미 포인트 F1의 바탕이다.

코드는 [PR #1](https://github.com/SeanKim0719/bakery-shop-simulator/pull/1)로 `main`에 병합되었다 (2026-11-12). 남은 일은 병합한 코드를 Unity에서 확인하고, 그 과정에서 나온 버그 두 건을 트러블슈팅 기록으로 남기는 것이다. 설계는 [04. 플레이어와 상호작용](../design/04-player-interaction.md)에 있다.

## M1-01. 병합한 조작 코드 확인

**목적**: `main`에 병합한 조작 코드가 Unity에서 의도대로 동작하는지 확인하고, 빠진 파일을 채운다.

진행 기록:

- 2026-11-12 병합 직후 점검: 병합은 정상. 버그 수정에서 추가된 파일 4개의 `.meta`가 빠져 있었고(수정이 Unity에서 실행된 적이 없었다), 이후 추가했다.
- 2026-11-12 두 번째 플레이 테스트: 버그 1의 수정이 탁자 앞에서 박스가 화면을 가리는 문제를 만들었고, 버그 2는 고쳐지지 않았다. [PR #49](https://github.com/SeanKim0719/bakery-shop-simulator/pull/49)로 다시 고쳤다.
- 2026-11-12 세 번째 플레이 테스트: 두 문제 모두 사라진 것을 확인했다. 버그 2의 원인(가설 3)은 Auto Sync Transforms 설정으로 검증했다 ([TS-002](../troubleshooting/TS-002-drop-physics-pose-sync.md)).

**Unity에서 확인**

- [ ] Unity로 프로젝트를 연다. Sourcetree에 `.meta` 파일 4개가 새로 보이면 커밋한다 (`chore: 누락된 meta 파일 추가`).
- [ ] Console에 컴파일 오류가 없다.
- [ ] Test Runner → EditMode → Run All: 53개가 모두 통과한다.
- [ ] 메뉴 **BakeryShop → 그레이박스 씬 만들기 (1주차)**로 씬을 다시 만들고 플레이한다. 콘솔에 오류가 없다. 바뀐 씬 파일을 커밋한다.
- [ ] WASD로 걷고 마우스로 둘러본다. 벽과 가구를 통과하지 않는다. 위아래 시점이 ±80도에서 멈춘다. 25cm 턱을 올라간다.
- [ ] 박스를 바라보면 `[E] 배송 박스 들기`가 뜨고(한글이 □로 나오지 않는다), E를 누르면 손에 든다.
- [ ] 박스를 든 채 바닥을 보면 `[E] 내려놓기`가 뜨고, 놓인 박스가 바닥에 반듯하게 선다.
- [ ] 박스를 든 채 다른 박스의 윗면을 보고 E를 누르면 그 위에 쌓인다. 3단까지 쌓아도 무너지지 않는다.
- [ ] G를 누르면 앞에 떨어뜨린다.
- [ ] **버그 1 확인**: 박스를 든 채 벽과 파란 가구에 바짝 붙으면 박스가 파고들지 않고 화면 아래쪽으로 내려가며 몸 쪽으로 접힌다. 물러서면 원래 위치로 돌아온다.
- [ ] **버그 1 확인 (시야)**: 박스를 든 채 탁자에 다가가 탁자 윗면을 내려다본다. 박스가 화면을 가리지 않고 조준점과 탁자 윗면이 보인다. `[E] 내려놓기`로 탁자 위에 올릴 수 있다.
- [ ] **버그 2 확인**: 박스를 든 채 발 앞 바닥(바로 아래에서 조금 앞)을 보고 내려놓는다. 플레이어가 위로 올라가지 않고, 박스가 날아가지 않고, 본 자리에 놓인다. 10번 반복한다.
- [ ] **버그 2 확인 (먼 자리)**: 1~2m 앞 바닥에 내려놓을 때 몸이 뒤로 밀리지 않는다.
- [ ] Esc를 누르면 커서가 풀리고, 다시 누르면 잠긴다.

**확인하면서 적어 둘 것**: 들고 걷는 느낌에서 어색한 점 (박스가 시야를 너무 가리는지, 당겨질 때 튀는지, 내려놓는 위치가 예상과 다른지). 수치는 `Hands`와 `PlayerMotor`의 인스펙터에서 바꿔 보고, 좋았던 값을 이 작업의 이슈에 댓글로 남긴다.

**의존**: 없음

## M1-02. 트러블슈팅 기록 2건

**목적**: 첫 플레이 테스트에서 나온 버그 두 건을 포트폴리오에 쓸 수 있는 기록으로 남긴다.

수정은 끝났지만 기록은 커밋 메시지에만 있었다. 트러블슈팅 템플릿으로 이슈 두 건([#2](https://github.com/SeanKim0719/bakery-shop-simulator/issues/2), [#3](https://github.com/SeanKim0719/bakery-shop-simulator/issues/3))을 만들고 커밋 메시지에서 옮길 수 있는 내용(현상, 원인, 해결, 버린 대안)을 채워 두었다. 남은 것은 Unity에서 직접 확인해야 하는 부분이다: 수정 전후 GIF, 재현 횟수, 버그 2의 가설 검증 결과, 배운 점.

| 이슈 | 현상 | 수정 | 기록할 핵심 |
| --- | --- | --- | --- |
| #2 손에 든 물건이 벽에 파고든다 | 박스를 들고 벽이나 가구에 다가가면 박스가 안으로 들어간다 | 1차 `8bce1fd`, 2차 PR "접어 들기" | 1차 해결(눈 쪽으로 당기기)이 **새 문제**(탁자 앞에서 박스가 화면을 가림)를 만들었고, 당기는 방향을 화면 아래쪽으로 바꿔 해결한 과정 |
| #3 내려놓으면 플레이어가 위로 올라간다 | 박스를 발 앞에 내려놓으면 플레이어가 올라가고, 가끔 박스가 날아간다 | 1차 `ba0edc2`, 2차 PR "물리 자세 동기화" | 가설 1(스킨 두께)로 고쳤지만 **버그가 남아 가설이 틀렸음을 확인**했고, 가설 3(콜라이더를 켜는 순간 물리 엔진의 자세가 옛 자리)으로 넘어간 과정 |

두 건 모두 "첫 해결이 틀렸거나 부작용이 있었다 → 다시 가설을 세웠다"는 흐름이 있어서 포트폴리오에 쓰기 좋다. 틀린 가설도 지우지 말고 남긴다.

**버그 2의 검증 결과** (2026-11-12)

가설 3: 내려놓는 순간 Transform은 새 자리로 옮겼지만 물리 엔진은 다음 FixedUpdate까지 박스를 "들고 있던 자리"(아래를 볼 때는 플레이어 몸 안)에 두고 있고, 그 상태로 콜라이더가 켜져서 CharacterController가 밀려 올라간다.

| 조건 | 결과 |
| --- | --- |
| 수정 전 코드, Auto Sync Transforms 끔 | 버그가 생긴다 |
| 수정 전 코드, Auto Sync Transforms **켬** | 버그가 사라진다 → 가설 3 확인 |
| 수정 후 코드(PR #49), Auto Sync Transforms 끔 | 버그가 사라진다 |

정리본 초안은 [TS-002](../troubleshooting/TS-002-drop-physics-pose-sync.md)에 있다. 남은 것은 GIF와 재현 횟수다. 수정 전의 모습은 `git checkout f3eda85`로 되돌려 찍을 수 있다 (찍은 뒤 `git checkout main`).

**남길 증거**: 수정 전후 GIF 각 1개, 재현 횟수(예: 10번 중 7번 → 0번), Scene 뷰 캡처.

**Unity에서 확인**

- [ ] 이슈 두 건이 템플릿의 모든 항목(현상, 가설, 검증, 원인, 해결, 결과)을 채우고 있다.
- [ ] 각 이슈에 수정 전후 GIF가 붙어 있다.

**의존**: M1-01
