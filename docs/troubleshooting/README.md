# 트러블슈팅

이 프로젝트에서 가장 중요하게 남기는 기록이다. 기능 목록이 아니라 "문제를 어떻게 발견하고, 원인을 좁히고, 해결을 수치로 검증했는가"를 보여준다.

## 해결 사례

| 번호 | 문제 | 분류 | 결과 |
| --- | --- | --- | --- |
| - | 개발 진행에 따라 추가 | - | - |

정리본 파일명은 `TS-001-짧은-제목.md` 형식을 쓴다.

## 기록 방식

1. 문제가 생긴 그날 GitHub Issue로 남긴다 (템플릿: `.github/ISSUE_TEMPLATE/troubleshooting.md`). 나중에 기억으로 쓰면 가설과 실패한 시도가 사라지는데, 면접에서 파고드는 부분이 바로 그것이다.
2. 해결 커밋 메시지에 이슈 번호를 연결한다 (예: `fix: 손에 든 박스 떨림 수정 (#12)`).
3. 전후 GIF와 프로파일러 캡처를 이슈에 붙인다.
4. 결과는 반드시 수치로 남긴다. "프레임 드랍 해결"이 아니라 "손님 N명 기준 몇 fps에서 몇 fps로" 같은 형태다.
5. 고른 방법과 버린 대안을 함께 적는다. 면접에서 가장 많이 받는 질문이 "왜 그 방법이었나, 다른 방법은?"이다.
6. 가장 깊게 파고든 3~4건만 이 폴더에 정리본으로 옮기고 README에서 링크한다. 성능·구조·밸런스처럼 서로 다른 분류에서 고른다.

## 예상되는 문제 후보

아래는 이 장르에서 흔히 생기는 문제 후보다. 미리 계측을 준비하기 위한 목록이며, 포트폴리오에는 실제로 겪고 해결한 것만 쓴다. 문제가 잘 드러나지 않으면 손님 수를 크게 늘리는 스트레스 테스트처럼 한계까지 밀어 일부러 찾는다.

| 문제 | 예상 원인 | 접근 방향 | 남길 증거 |
| --- | --- | --- | --- |
| 손에 든 물건이 벽·선반을 뚫거나 떨림 | Rigidbody와 Transform 직접 이동의 충돌 | 드는 동안 kinematic 전환, 레이어 분리, 손 전용 카메라 | 전후 GIF |
| 손님끼리 계산대 앞에서 끼이거나 밀림 | NavMesh 회피의 한계 | 줄 서기 슬롯 큐로 목적지 분리, 회피 우선순위 조정 | 손님 다수 테스트 영상 |
| 손님이 늘면 프레임 드랍 | Update 남발, Instantiate와 GC, 경로 재계산 | 프로파일러로 병목 확인 후 풀링, 틱 매니저, 재계산 주기 제한 | 프로파일러 캡처, fps 전후 |
| 로드 후 선반 재고가 어긋나거나 중복 | 오브젝트 참조는 직렬화 불가, 로드 순서 | 고유 ID 레지스트리, 생성 후 참조 연결의 2단계 로드 | 재현 테스트 |
| 박스 확률이 체감상 너무 짜거나 후함 | 순수 랜덤의 연속 꽝 | 천장, 시뮬레이션으로 분포 확인, 밸런스 시트 | 시뮬레이션 분포 그래프 |
| 일시정지 후 오븐 타이머·신선도 어긋남 | 게임 시간과 실제 시간 혼용 | TimeManager를 단일 시간 소스로 | 단위 테스트 |
| 최고가로만 팔아도 이득인 밸런스 붕괴 | 가격 대비 구매 확률 곡선 설계 | 자동 플레이 시뮬레이션으로 최적 전략 확인 후 곡선 조정 | 가격별 수익 그래프 |
| 가구 배치 후 손님이 갇힘 (MVP 이후) | 런타임 NavMesh 갱신 | 배치 전 경로 검증 | 전후 GIF |
